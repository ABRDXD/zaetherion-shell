Reading it:
- fartd-cpp's RSS is mostly shared clean mappings (18.5 MiB): libQt6Core, ICU (libicudata alone is large),
  glib, libstdc++. Quickshell maps the same libQt6Core and ICU, so on the desktop those pages are shared with
  the view; PSS above already divides them among every process mapping them on this machine.
- What the C++ core owns (private dirty) is 1.3 MiB idle vs 14.7 MiB for Python. The +0.9 MiB after the burst
  is malloc keeping the arena the 10,000 queued lines and replies used.
- Stage 0 holds almost no state; later stages add theirs. Re-measure at each stage.
- Side finding: the Python core idles at ~24.9 MiB RSS here, 150 KiB under the lifecycle scenario's 25 MiB
  (25,600 KiB) RSS check, so that check is close to failing on the Python core.
