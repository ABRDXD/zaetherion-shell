# Repository layout

The target architecture and budgets are in [PROJECT_PLAN.md](../PROJECT_PLAN.md#target-architecture). This file records where code lives now.

The repository root is the Quickshell shell root: `shell.qml` is the entry, and every directory is imported as a `qs.*` module (`import qs.view.ui`). Quickshell resolves those at runtime, including singletons and cyclic imports. Each module folder also keeps a real `qmldir` (approved 7 Nov 2026), generated by `tools/make_qmldirs.py` with the same lines Quickshell would synthesize. They let Qt's QML disk cache apply once Quickshell loads such folders by `file://` (#1434, [COLDSTART.md](COLDSTART.md)). After adding, renaming or removing a `.qml` file, or changing its `pragma Singleton` or `//@ pragma Internal`, run `python3 tools/make_qmldirs.py`. `tests/test_qmldirs.py` fails until you do. The root keeps no `qmldir`. `Quickshell.shellPath()` paths are relative to the root.

## State

The core owns `tasks.json`, `timers.json` (version 2), `notifications.json`, `overdrive.json`, `session.json`, `sessions.jsonl`, `discovery.json` and `core.json`. It migrated `todo.json` (kept untouched) and version 1 `timers.json` (backed up as `timers.v1.json`). The view writes only `preferences.json` and `settings.json`. Both live in `$FART_STATE_DIR`; the launcher sets it to `~/.local/state/fart-next` and, on first start, copies the archive's `~/.local/state/fart` files that are not already there, including the portrait. Existing destination files always win, and the archive's files are never written. Without the variable the view falls back to `$XDG_STATE_HOME/fart`, which is what the cutover will use. The launcher also sets `FART_CACHE_DIR=~/.cache/fart-next` (FART's lyrics cache). Without it the fallback is `$XDG_CACHE_HOME/fart`. Host files (palette, settings, EQ state, lyrics cache) are read only by `adapters/serpantinum`, whose `core.py` is the core's host profile. The core's runtime files (`core.sock`, `core.lock`, `core.log`, `launch.lock`) live in `$XDG_RUNTIME_DIR/fart-next`.

## How M0 was seeded

The live generated package (`$XDG_RUNTIME_DIR/fart/b096a31ea890/package`, byte-identical to a fresh build of archive `f442c93`) was copied file by file into this layout. Relative directory imports became `qs.*` imports computed from the type names each file uses. The only other source edits:

- `view/shell/Shell.qml`: room loader paths gained `../rooms/`.
- `view/compat/Directories.qml`: `fartState` (`$FART_STATE_DIR`), and `scriptPath` now points at `tools/` instead of the archive's `scripts/` via `FART_SOURCE`.
- `Persistent`, `Config`, `ViewState`, `Directories.todoPath`: use `fartState`.
- `adapters/serpantinum/GlobalStates.qml`: `cava.conf` moved to `tools/`.
- `view/compat/DotsUpdater.qml`: Update FART runs `fart-next update` (read-only report) instead of the archive's merge updater.
- `tools/lyrics/lyrics.py` copied from the archive's `scripts/lyrics/`.
